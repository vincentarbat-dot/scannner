## Технологический стек (решено, не менять без причины)

- **Frontend**: React 19 + TypeScript + Vite, роутинг — react-router-dom.
- **Стили**: Tailwind CSS v4 (через `@theme` в `src/index.css`, конфиг
  `postcss.config.js`, `tailwind.config.js` не используется — v4 не требует).
- **БД / Auth / Storage**: Supabase (Postgres + RLS, email-auth, Storage
  buckets `originals` / `processed` / `pdfs`).
- **Деплой**: Netlify (`netlify.toml` уже настроен — SPA redirect,
  `camera` permission header).
- **QR/штрихкод**: `@zxing/library` установлен, использование — Часть 3.
- **Offline-очередь**: `idb` установлен, использование — Часть 4 (раздел 23 ТЗ).
- Claude **не имеет** сетевого доступа к netlify.com / supabase.com из
  песочницы — создание проектов и реальный деплой всегда делает пользователь
  по инструкции в README.md. Код и конфиги готовятся полностью заранее.

## Дизайн (решено)

Токены — в `src/index.css` (`@theme`). Цвета: `--color-ink` (текст),
`--color-paper` (фон), `--color-accent` (тёмно-зелёный, основной acцент),
`--color-stamp` (тёплый терракотовый — статусы/акценты, отсылка к печати
на накладной). Шрифты: display — Fraunces (заголовки), body — Inter,
mono — IBM Plex Mono (числа, суммы, номера документов). Сигнатурный элемент
— уголки видоискателя камеры (`.viewfinder-corners` в index.css),
используются на карточках и на главном экране — отсылка к автоопределению
границ документа (раздел 3 ТЗ). Не менять палитру/шрифты без явного запроса
пользователя — уже сделан осознанный выбор, чтобы не съезжать к дефолтным
AI-стилям.

## Часть 3 — Обработка, распознавание, сохранение ✅ ГОТОВО (кроме OCR — см. ниже)

Соответствует разделам 5-11, 14-15, 19-20 ТЗ. **OCR (раздел 13) сознательно

подключение OCR-движка отложены до Части 5, решение уже принято в пользу
**PaddleOCR** (не Tesseract.js, как было предварительно намечено в
PROGRESS.md после Части 2 — это решение теперь считать устаревшим).
Карточка накладной ниже полностью готова принять результат OCR, когда он
появится — сейчас поля заполняются и правятся вручную (раздел 13 и так
требует такой возможности).

Что сделано:
- [x] `src/lib/imageProcessing.ts` — обработка кадра на canvas: обрезка по
      границам документа (только если bounds уверенные — не касаются края
      и покрытие кадра разумное, иначе кадр не режется, раздел 7),
      шумоподавление (мягкий box blur, смешанный с оригиналом), выравнивание
      освещения/уменьшение теней (деление на крупный box-blur "фон",
      классический flat-field приём), автоконтраст по перцентилям
      гистограммы, повышение резкости (unsharp mask с умеренным
      коэффициентом — сильный шарпен может сломать геометрию QR, раздел 8),
      ограничение размера/переэкодирование в JPEG (раздел 5 "оптимизация
      размера файла"). Цветной режим по умолчанию (раздел 10); ч/б и
      градации серого — доступны как опция `processPage()`, но не

      Оригинал (`page.blob`) в обработку не передаётся вообще — он грузится
      в Storage отдельно и без изменений (раздел 6).
- [x] `src/lib/codes.ts` — детект QR/штрихкод/Data Matrix через
      `@zxing/library` (MultiFormatReader + HybridBinarizer +

- [x] `src/lib/imageQuality.ts` — добавлена `scoreDocumentOverall()`:

- [x] `src/lib/uploadDocument.ts` — оркестрация сохранения: создаёт

Осознанно не сделано / упрощено:
- Удаление документа в админ-панели не удаляет связанные файлы из Storage

  делалась — офлайн-очередь решает только "сеть пропала ПОСЛЕ того как
