# ТЗ: Мобильный сайт для сканирования накладных поставщиков

## 1. Назначение проекта

Разработать мобильный веб-сайт для фотографирования, обработки, распознавания и хранения накладных от поставщиков.

Основная задача сайта — позволить сотруднику быстро сфотографировать накладную на обычный телефон, даже если камера телефона имеет невысокое качество, и получить чёткую электронную копию для бухгалтерии.

Особое внимание уделить сохранению **текста, печатей, подписей, QR-кодов, штрихкодов, Data Matrix и банковских реквизитов**, которые могут использоваться бухгалтерией для проверки документов и оплаты.

---

# 2. Основной сценарий работы

Пользователь открывает сайт с телефона.

На главном экране:

* **Сканировать накладную**
* **Архив документов**
* **Поиск**
* **Настройки**

Пользователь нажимает **«Сканировать накладную»**.

Открывается камера телефона.

Система автоматически определяет документ и показывает его границы.

Пользователь наводит камеру на накладную.

Система анализирует качество изображения.

Если качество достаточное — фотография автоматически создаётся либо пользователь нажимает кнопку съёмки.

После фотографирования изображение автоматически обрабатывается.

Система проверяет результат и показывает:

**✓ Документ читаемый**

**✓ QR-код читаемый**

**✓ Печать обнаружена**

**✓ Документ полностью попал в кадр**

После этого пользователь нажимает:

**«Сохранить»**

---

# 3. Умная камера

Камера должна работать непосредственно через браузер телефона.

Необходимо использовать максимально доступное разрешение камеры устройства.

Система должна автоматически определять:

* границы листа;
* углы документа;
* положение документа;
* ориентацию;
* наклон;
* освещение;
* резкость;
* наличие бликов;
* наличие перекрытий;
* полноту документа в кадре.

На экране должна отображаться рамка документа.

При правильном расположении:

**«Документ обнаружен»**

Если документ расположен неправильно:

**«Наведите камеру на весь документ»**

Если слишком темно:

**«Недостаточно освещения»**

Если изображение размыто:

**«Удерживайте телефон неподвижно»**

Если присутствует сильный блик:

**«Измените угол съёмки»**

---

# 4. Автоматическое фотографирование

Предусмотреть возможность автоматического создания фотографии после того, как система определила:

* документ полностью находится в кадре;
* границы документа определены;
* камера относительно стабильна;
* освещение находится в допустимом диапазоне;
* резкость достаточная.

Также должна оставаться возможность сделать фотографию вручную.

---

# 5. Обработка фотографии

После фотографирования система автоматически выполняет обработку документа.

Необходимо предусмотреть:

* коррекцию перспективы;
* выравнивание документа;
* автоматическую обрезку;
* поворот;
* повышение резкости;
* повышение читаемости текста;
* устранение цифрового шума;
* коррекцию яркости;
* коррекцию контрастности;
* выравнивание освещения;
* уменьшение теней;
* устранение лишнего фона;
* оптимизацию размера файла.

Обработка должна быть адаптирована под фотографии, сделанные камерами низкого качества.

---

# 6. Сохранение оригинала

Оригинальная фотография должна сохраняться отдельно.

Система не должна заменять оригинальный файл обработанной версией.

Для каждого документа должны храниться:

**Оригинал**

и

**Обработанная версия**

Это необходимо для возможности повторной обработки документа и проверки оригинала.

---

# 7. Защита важных элементов документа

Система не должна применять обработку, которая может уничтожить или исказить важную информацию.

Особое внимание уделить:

* QR-кодам;
* штрихкодам;
* Data Matrix;
* печатям;
* подписям;
* рукописным отметкам;
* банковским реквизитам;
* номерам документов;
* серийным номерам;
* мелкому тексту.

---

# 8. QR-коды

Система должна автоматически обнаруживать QR-коды на накладной.

После обработки необходимо проверить возможность их считывания.

Если QR-код читается:

**✓ QR-код читаемый**

Если QR-код обнаружен, но качество недостаточное:

**⚠ QR-код плохо читается**

Пользователь должен получить предложение переснять документ.

Обработка не должна изменять геометрию QR-кода таким образом, чтобы он перестал считываться.

По возможности QR-код должен обрабатываться отдельно от остального изображения.

---

# 9. Штрихкоды и Data Matrix

Система должна обнаруживать и сохранять:

* обычные штрихкоды;
* QR-коды;
* Data Matrix;
* другие машинно-считываемые коды, используемые на накладных.

После обработки должна выполняться проверка их читаемости.

---

# 10. Печати и подписи

Система должна сохранять печати и подписи в максимально возможном качестве.

Необходимо сохранять:

* цвет печати;
* контуры печати;
* подписи;
* рукописные записи;
* штампы;
* факсимиле.

Чёрно-белый режим не должен применяться автоматически, если он ухудшает читаемость печати или подписи.

Основной режим для важных документов — **цветное сканирование**.

---

# 11. Контроль качества

После обработки система должна автоматически оценивать документ.

Проверять:

* резкость;
* читаемость текста;
* наличие всего документа;
* качество QR-кодов;
* качество штрихкодов;
* наличие печатей;
* наличие подписей;
* качество изображения;
* наличие сильных бликов;
* наличие сильных теней.

Показывать общий показатель:

**Качество документа: 94%**

При недостаточном качестве:

**«Документ может быть плохо читаемым. Рекомендуется переснять.»**

Пользователь должен иметь возможность:

**«Переснять»**

или

**«Сохранить всё равно»**

---

# 12. Несколько страниц

Одна накладная может состоять из нескольких страниц.

Пользователь должен иметь возможность добавить несколько фотографий.

Пример:

**Страница 1/3**

**Страница 2/3**

**Страница 3/3**

После завершения система объединяет все страницы в один документ.

Пользователь может:

* менять порядок страниц;
* удалять страницу;
* переснимать страницу;
* добавлять новую страницу.

---

# 13. OCR — распознавание текста

Система должна поддерживать OCR.

Из накладной необходимо по возможности автоматически распознавать:

* название поставщика;
* БИН;
* ИИН;
* номер накладной;
* дату;
* номер документа;
* наименование товаров;
* количество;
* единицы измерения;
* цену;
* сумму;
* НДС;
* итоговую сумму;
* банковские реквизиты.

Распознанная информация должна отображаться пользователю.

Пользователь должен иметь возможность исправить распознанные данные вручную.

---

# 14. Распознавание QR

Если QR-код содержит информацию о документе, необходимо предусмотреть возможность его автоматического считывания.

После обнаружения QR-кода система может отображать:

**QR-код обнаружен**

**Данные QR-кода доступны**

Необходимо предусмотреть возможность сохранения распознанной информации вместе с накладной.

---

# 15. Карточка накладной

После сохранения создаётся карточка документа.

Карточка должна содержать:

* поставщика;
* БИН;
* номер накладной;
* дату;
* сумму;
* НДС;
* количество страниц;
* дату загрузки;
* сотрудника;
* статус;
* оригинальные фотографии;
* обработанные фотографии;
* PDF;
* распознанные данные;
* информацию о QR-кодах.

---

# 16. Архив документов

Создать раздел **«Архив»**.

В архиве отображаются все накладные.

Для каждого документа отображать:

* дату;
* поставщика;
* номер;
* сумму;
* статус;
* количество страниц;
* наличие QR-кода;
* качество документа.

---

# 17. Поиск

Реализовать поиск по:

* поставщику;
* БИН;
* номеру накладной;
* дате;
* сумме;
* сотруднику;
* статусу.

Добавить фильтрацию по периоду.

---

# 18. Статусы документов

Предусмотреть статусы:

* **Новый**
* **Проверен**
* **Передан бухгалтерии**
* **Обработан**
* **Архив**

Статус должен изменяться вручную либо автоматически в зависимости от настроек системы.

---

# 19. Создание PDF

После завершения сканирования система должна автоматически создавать PDF.

PDF должен:

* иметь правильную ориентацию;
* содержать все страницы;
* сохранять читаемость мелкого текста;
* сохранять QR-коды;
* сохранять штрихкоды;
* сохранять печати;
* сохранять подписи;
* не содержать лишнего фона;
* быть оптимизирован по размеру.

Пользователь может скачать PDF.

---

# 20. Два варианта документа

Для каждой накладной должны быть доступны:

**Оригинал**

Фотография без обработки.

**Улучшенный документ**

Обработанная версия для бухгалтерии.

Пользователь должен иметь возможность скачать оба варианта.

---

# 21. Повторная обработка

Для уже загруженной накладной предусмотреть кнопку:

**«Улучшить документ»**

Пользователь может повторно применить обработку.

Доступные варианты:

* улучшить качество;
* повысить резкость;
* убрать тени;
* улучшить контраст;
* цветной режим;
* оттенки серого;
* чёрно-белый режим.

Оригинал при этом не изменяется.

---

# 22. Интерфейс

Сайт должен быть **mobile-first**.

Основное использование — смартфон.

Интерфейс должен быть максимально простым.

Необходимо минимизировать количество действий.

Основной сценарий должен занимать:

**Открыть → Сканировать → Сфотографировать → Проверить → Сохранить**

Кнопки должны быть крупными и удобными для использования одной рукой.

---

# 23. Работа при плохом интернете

Необходимо предусмотреть возможность временного сохранения фотографии на устройстве, если интернет нестабильный.

После восстановления соединения документ должен автоматически отправляться на сервер.

Пользователь должен видеть статус:

**Ожидает загрузки**

**Загрузка**

**Загружено**

**Ошибка загрузки**

При ошибке должна быть кнопка:

**«Повторить»**

---

# 24. Безопасность

Все документы должны передаваться по защищённому соединению.

Файлы должны храниться в защищённом хранилище.

Необходимо реализовать разграничение доступа.

Сотрудник должен видеть только разрешённые ему документы.

Бухгалтер должен иметь доступ к необходимым документам и архиву.

---

# 25. Панель администратора

Предусмотреть отдельную административную часть.

Администратор должен иметь возможность:

* просматривать документы;
* искать документы;
* удалять документы;
* изменять статусы;
* просматривать пользователей;
* управлять доступом;
* просматривать ошибки обработки;
* просматривать качество сканирования;
* скачивать документы.

---

# 26. Аналитика

Предусмотреть статистику:

* количество накладных;
* количество документов за день;
* количество документов за месяц;
* количество документов по поставщикам;
* количество некачественных сканов;
* количество пересъёмок;
* количество документов, переданных бухгалтерии.

---

# 27. Главный приоритет системы

Главная задача — **не просто сделать фотографию**, а получить максимально качественную цифровую копию реальной накладной.

Система должна самостоятельно помогать сотруднику сделать правильный снимок, исправлять перспективу и качество изображения, но при этом **не уничтожать информацию, необходимую бухгалтерии**.

Особый приоритет:

**Текст → QR-код → штрихкод → печать → подпись → банковские реквизиты → общее качество документа.**

Итоговый документ должен быть пригоден для просмотра, печати, хранения и использования бухгалтерией.
